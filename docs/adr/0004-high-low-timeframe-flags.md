# High and low timeframe flags, with no `--timeframe` alias

`--high_timeframe` replaces `--timeframe`, and `LOW_TIMEFRAME` replaces `EXECUTION_TIMEFRAME`. "Signal timeframe" and "execution timeframe" did not say which bar size was the larger, and a strategy such as `choch_sr` reads both. `--timeframe` now fails with a message naming `--high_timeframe` instead of being kept as an alias. An alias would keep the ambiguous name working in saved commands and docs, so it would never go away, and once `--low_timeframe` exists a reader of `--timeframe 5m` could not tell which of the two it sets. A broken command costs one edit, and the error says which.

`--low_timeframe` is accepted only by strategies that declare `LOW_TIMEFRAME`. ADR 0003 deferred 1-minute fills for higher timeframes because strategies receive low-timeframe bars, so a flag would silently change the strategy: `ema50` given 1m bars computes its EMA on 1m bars. A strategy that declares `LOW_TIMEFRAME` has already said it reads triggers on smaller bars and builds its own context, so varying that bar size is the comparison it was written for. Any other strategy keeps a low timeframe equal to its high timeframe and rejects the flag.
